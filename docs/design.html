Workspace Collections MCP

Approved design · 2026-09-10 · repo wayneadams/collections-mcp · spec design.md

Grok Build greps source. It does not keep a durable semantic index of the prose across this workspace. This design adds a search-only MCP plus an offline ingest job that uses the xAI Collections API as hosted RAG.

Agents in Grok Build, Cursor, and Claude Code call four tools. They never create, upload, or delete collections. File-type coverage is a typed ingest pipeline: native MIME pass-through, a short named convert list, and skip everything else.

Two processes, two keys

Ingest path

File types

Feasibility bar: UTF-8 text, or a Collections special MIME, or a named Windows library that yields useful RAG text under 100MB. Files over 100MB are skipped, not split. Converter exceptions skip the file and continue the run.

MCP tools

Server name collections. Grok qualifies them as collections__…. BM25 tool discovery wants a small surface. Hybrid retrieval, default limit 8, payload budget 18_000 bytes against Grok’s 20_000-byte cap.

collections_search

REST POST /v1/documents/search. Exact AIP-160 filters on repo, identity, path. Ranked chunks with abs_path and collections:// citation. Not grep.

list_collections

Local SQLite. Names and ids so the agent does not guess collection_… strings.

list_documents

Local SQLite. Filter by repo or identity. Metadata only.

get_document

Local file or conversion artifact when include_content. No $0.20/GiB download of hosted bytes. Binaries refused.

Not on the MCP: create, upload, update, delete, reindex, destroy. Those stay on collections-sync.
